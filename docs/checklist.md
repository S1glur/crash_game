# Приёмочный чек-лист

По этому файлу сверяемся мы сами и, по сути, проверяют эксперты — сценарии 1–5
взяты из постановки задачи дословно. Задача считается сделанной не когда
«эндпоинт написан», а когда соответствующий пункт здесь проходится руками в
браузере от начала до конца.

Отмечать: `[ ]` не сделано → `[~]` работает частично → `[x]` проходится целиком.

**Важно про текущее состояние:** почти всё стоит в `[~]`. Код написан и собирается,
контракт сверен с живым сервером, но **вёрстка и анимации ещё ни разу не открывались
в браузере глазами** — ни на десктопе, ни на узких экранах. Переводить в `[x]` можно
только после того, как пункт реально прокликан руками.

## Сценарий 1. Выбор ставки и запуск игры — обязательный

- [~] Экран выбора ставки открывается сразу после входа (без стартового экрана темы)
- [~] Видны 4 варианта ставки: без бустера, ×2, ×3, ×4 — с ценой и множителем
- [~] Видна история завершённых игр (всех пользователей, с коэффициентами)
- [~] Правила игры открываются ДО подтверждения ставки и объясняют механику
- [~] Переключение темы меняет количество уровней: 12 (красная) / 9 (зелёная)
- [~] Вариант дороже баланса — неактивен, при клике тост «Не хватает бонусов»
- [~] Кнопка «Начать» активна только после выбора доступного варианта
- [~] При «Начать»: анимация активации → списание с баланса → игровой экран

## Сценарий 2. Успешный cashout и результат раунда — обязательный

- [x] Шар летит, коэффициент растёт в реальном времени (данные с сервера)
- [~] «Забрать» некликабельна до 1-го уровня, дальше активна
- [x] Нажатие «Забрать» на ~2.5: выигрыш = ставка × коэффициент зачислен на баланс
- [~] Показано сообщение «Могли бы забрать больше»
- [x] Шар продолжает лететь и лопается, итог при этом не меняется
- [~] Экран результата открывается только ПОСЛЕ краха
- [~] На экране результата: выигрыш, коэффициент, очки за раунд, награда
- [~] Раунд появился в истории игр
- [~] «Играть снова» возвращает к выбору ставки с сохранением темы
- [~] Бездействие 10 секунд на экране результата → автопереход

## Сценарий 3. Проигрыш (crash) — обязательный

- [~] Не нажимаем «Забрать» → шар лопается, анимация взрыва
- [x] Ставка сгорает полностью
- [~] Экран проигрыша: коэффициент краха + заработанные за раунд очки
- [x] Награда за раунд выдаётся и при проигрыше тоже
- [~] Раунд попал в историю, можно начать новый

## Сценарий 4. Активация бустера — обязательный

- [~] При ставке с бустером на одном из уровней виден маркер бустера
- [x] Позиция маркера меняется от раунда к раунду (генерируется сервером)
- [x] Шар долетел до уровня бустера → коэффициент резко вырос (×N)
- [~] Начислены дополнительные очки, есть визуальный + звуковой эффект
- [x] Cashout после бустера считается с учётом бустера
- [x] Бустер НЕ срабатывает, если «Забрать» нажали раньше

## Сценарий 5. Управление параметрами — обязательный

- [x] `points_per_line` меняется в `config/game.json` без правки кода
- [x] Новое значение применяется к следующему раунду (hot-reload / перезапуск)
- [x] В новом раунде за уровень начисляется новое количество очков
- [x] Порядок применения настроек описан в документации
- [ ] Аналогично проверяются: множители бустеров, вероятности позиции бустера,
      параметры мат. модели

## Как проверять свою половину в одиночку

**Backend без фронта:**
- `docs/api.http` — все запросы контракта, открыть в VS Code REST Client
- `localhost:8080/ws-test.html` — страница, печатающая поток STOMP-событий
- Проверка мат. модели — серией запусков с разными seed, а не одним раундом

**Frontend без бэка:**
- Мок по контракту (msw), обязательно с разными вариантами данных:
  ранний крах, крах после бустера, ошибка `INSUFFICIENT_BALANCE`

**Оба:** dev-режим с фиксированным seed (см. `docs/api.md` → «Dev-режим») —
единственный способ воспроизводимо проверять сценарии 3 и 4, не полагаясь на
удачу.
